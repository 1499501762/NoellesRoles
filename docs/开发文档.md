# NoellesRoles 开发文档

本开发文档面向参与 NoellesRoles 的开发者，概述项目结构、角色系统的组件划分与注册方式、组件间的交互流程，以及编写规范与示例代码骨架，帮助你快速、安全地扩展功能。

## 目录结构

- 根目录构建与配置
  - `build.gradle`、`settings.gradle`、`gradle.properties`：Gradle 构建配置与项目设置。
  - `gradlew`、`gradlew.bat`、`gradle/wrapper/gradle-wrapper.properties`：Gradle Wrapper 跨平台启动。
  - `README.md`、`LICENSE.txt`：项目说明与许可证。
- 源码与资源
  - `src/main/java`：服务端/公共逻辑代码，入口类、注册类、角色与组件实现。
  - `src/main/resources`：`fabric.mod.json`、`noellesroles.mixins.json` 等资源、数据包与素材。
  - `src/client/java`：客户端专属逻辑（渲染、HUD、输入等）。
  - `src/client/resources`：客户端资源（如语言文件、图标）。
- 运行与开发输出（自动生成）
  - `build/`：编译产物、生成的源、报表、打包的 Jar 等。
  - `run/`：开发环境运行目录（日志、配置、崩溃报告、存档等）。

提示：使用 VS Code Tasks（或命令行）运行：

```
gradle runClient --debug-jvm
gradle runServer --debug-jvm
```

## 技术栈与关键依赖

- Fabric 平台：`fabric.mod.json` 声明 Mod 元数据与入口，`mixins` 注入运行时行为。
- Cardinal Components API：为实体（玩家等）挂载可同步的组件（状态、角色数据）。
- Fabric API 事件：通过事件回调（交互、攻击、使用物品等）驱动能力与条件判断。

## 角色系统总览

一个“角色”由若干组件组成，负责标识、能力、条件、触发与状态持久化：

- 标识组件（`RoleComponent`）
  - 内容：`roleId`（`Identifier`）、`assignedAt`（时间戳/纪元）、`state`（自定义状态）。
  - 作用：声明玩家当前角色，负责与客户端同步与持久化（NBT）。
- 能力组件（`AbilityComponent`）
  - 内容：能力集合、冷却与资源消耗、触发器（事件/主动技能）。
  - 作用：响应 Fabric 事件或主动调用，应用效果（伤害、移动、视野、标记等）。
- 条件组件（`ConditionComponent`）
  - 内容：上下文与规则（阵营、时间、地点、标签、次数、目标类型）。
  - 作用：在能力执行前进行授权校验，拒绝不满足条件的调用。
- 冷却/计时器（`CooldownManager`）
  - 内容：能力键 → 下次可用时间；Tick 驱动更新。
  - 作用：统一管理能力节流与可用性。
- 网络同步（`AutoSyncedComponent`）
  - 作用：将关键状态（角色、冷却等）从服务端同步到客户端以驱动 UI 展示。

数据驱动（可选）：在 `src/main/resources/data/noellesroles/roles/*.json` 定义角色元数据与默认能力集合，加载时注册到自定义 Registry 或内存表中。

## 注册与生命周期

### 入口与初始化

- `ModInitializer`：在 `onInitialize()` 完成注册：
  - 组件键注册：`ComponentRegistry.getOrCreate(id("role"), RoleComponent.class)`。
  - 实体组件挂载：`EntityComponentFactoryRegistry.INSTANCE.registerForPlayers(...)`。
  - 事件监听注册：Fabric API 相关回调（交互、攻击、Tick、物品使用等）。
  - 角色表加载：扫描数据包或代码静态表，建立 `roleId → Role` 映射。

### 组件挂载与复制策略

- 玩家实体组件：在玩家创建/重生时挂载，建议使用 `RespawnCopyStrategy.ALWAYS_COPY` 保留角色状态。
- 同步策略：实现 `AutoSyncedComponent`，在服务端变更时触发同步（避免客户端作弊源头）。

### 角色分配与切换

- 时机：首次加入、特定指令、任务达成、道具触发等。
- 流程：
  1. 校验条件（阵营/上下文）。
  2. 更新 `RoleComponent` 的 `roleId` 与状态。
  3. 重置/迁移能力与冷却。
  4. 同步到客户端并发出事件供 UI 与其他系统响应。

## 交互与事件流

- 基础事件（示例）：
  - 攻击事件：在 `AttackEntityCallback` 中检查当前角色与能力，应用特效或改写伤害。
  - 物品使用：在 `UseItemCallback` 中根据条件触发主动能力或角色专属交互。
  - Tick 驱动：在 `ServerTickEvents.START_WORLD_TICK` 中推进冷却与定时器，必要时批量同步。
- 组件协作：
  - `AbilityComponent` 请求 `ConditionComponent` 进行授权；通过 `CooldownManager` 检查节流；成功后调用效果层（如 `EffectApplier`）。
  - `RoleComponent` 决定可用能力集合与行为边界，切换时广播内部事件供其他组件重配置。

## 编写规范

- 包结构与命名
  - 建议：`com.yourorg.noellesroles.role`（角色）、`component`（组件）、`ability`（能力）、`condition`（条件）、`network`（网络）、`registry`（注册）、`mixin`（Mixin 注入）。
  - 公开 API（接口/数据结构）与内部实现分离，面向接口编程，利于测试与替换。
- 客户端与服务端分离
  - 客户端专属代码放在 `src/client/java`，必要时使用 `@Environment(EnvType.CLIENT)` 注解。
  - 任何可授权/判定逻辑必须在服务端进行，客户端只做显示。
- 序列化与同步
  - 组件实现 `Component` 与 `AutoSyncedComponent`，在 `readFromNbt` / `writeToNbt` 保持前后兼容。
  - 同步频次可控：仅在状态变更时同步，避免频繁广播。
- 日志与调试
  - 使用 `run/logs` 与 `run/crash-reports` 快速定位问题。
  - Mixins 注入点保持最小必要范围，避免与其他 Mod 冲突。

```java
// 入口类（src/main/java/.../NoellesRoles.java）
public class NoellesRoles implements ModInitializer {
    public static final String MODID = "noellesroles";
    public static final Identifier ROLE_ID = new Identifier(MODID, "role");

    public static final ComponentKey<RoleComponent> ROLE =
        ComponentRegistry.getOrCreate(ROLE_ID, RoleComponent.class);

    @Override
    public void onInitialize() {
        // 将角色组件挂载到玩家实体，重生时复制
        EntityComponentFactoryRegistry.INSTANCE.registerForPlayers(
            ROLE,
            player -> new RoleComponentImpl(),
            RespawnCopyStrategy.ALWAYS_COPY
        );

        // 注册事件（示例）
        AttackEntityCallback.EVENT.register((player, world, hand, target, hitResult) -> {
            RoleComponent rc = ROLE.get(player);
            if (rc != null && AbilityRegistry.canStrike(rc.getRoleId())) {
                // 应用角色能力效果...
            }
            return ActionResult.PASS;
        });

        // 加载数据驱动的角色表（如从 data/noellesroles/roles/*.json）
        RoleTable.loadAll();
    }
}
```

### UI 与商店实现注意事项

- **客户端/服务端职责分离**：所有授权、购买判断、物品授予、货币变更与触发副作用（例如触发 PSYCHO_MODE）必须在服务端完成。客户端仅负责显示、提示与发送用户意图（例如：想要购买第几个展示项）。
- **不要信任客户端索引或 ItemStack**：客户端发送的购买请求中带的索引或 ItemStack 都不能作为最终依据。服务端应使用内部的 `ShopEntry` 列表或受信任的注册表来决定授予什么物品，并构建/插入服务端的 `ItemStack` 实例。
- **商店索引映射（客户端 UI → 服务端索引）**：若客户端的展示顺序与服务端在运行时可能不同（例如按角色过滤、按权重排序），建议在客户端维护一个映射表 `displayIndex -> serverIndex`，在用户点击时把对应的 `serverIndex` 发给服务端；示例：

```java
// 客户端：点击 widget 时发送对应的服务端索引
int serverIndex = serverIndexMapping.get(widgetIndex);
ClientPlayNetworking.send(new BuyShopItemC2SPacket(serverIndex));

// 服务端接收（不要信任客户端给出的 ItemStack）
ServerPlayNetworking.registerGlobalReceiver(BuyShopItemC2SPacket.ID,
        (server, player, handler, buf, responseSender) -> {
                int index = buf.readInt();
                server.execute(() -> PlayerShopComponent.tryBuy(player, index));
        }
);
```

- **服务端保护 / Mixin 模式**：当某个商品需要特殊处理或按角色授权时，优先在服务端的 `tryBuy` 路径上做保护。例如使用 mixin 拦截 `PlayerShopComponent.tryBuy`（或在处理购买请求的中央处理器内）来：
    - 验证玩家角色/权限；
    - 从受信任的位置创建并插入 `ItemStack`；
    - 扣除货币并记录购买历史；
    - 避免在客户端 UI 与服务器索引不一致时产生的错误行为（如误触发致死/心理效果）。

- **示例（项目内实现参考）**：
    - 客户端 HUD/Shop：`src/client/java/org/agmas/noellesroles/client/mixin/gambler/GamblerHudMixin.java`, `src/client/java/org/agmas/noellesroles/client/mixin/gambler/GamblerShopMixin.java`。
    - 服务端购买保护：`src/main/java/org/agmas/noellesroles/mixin/gambler/GamblerPlayerShopComponentMixin.java`（在 `tryBuy` 中插入服务端 `ItemStack` 并扣款）。

## 商店系统注册与实现

### 商店架构

商店由以下组件构成：
- **商品数据**：`ShopItem` 封装商品 ID、名称、价格、图标、限购等。
- **商店表**：`ShopRegistry` 维护商店 ID → 商品列表映射。
- **交易逻辑**：验证库存、玩家货币、冷却；执行购买与同步。
- **UI 屏幕**：`ShopScreen` 展示商品列表、购买按钮、库存与冷却状态。

### 商品与商店注册

```java
// 商品定义（src/main/java/.../shop/ShopItem.java）
public class ShopItem {
    private final Identifier id;
    private final Component displayName;
    private final int price;  // 货币/积分单位
    private final ItemStack icon;  // 显示用图标
    private final int maxPurchases;  // 单个玩家最多购买次数（-1 表示无限）
    private final long cooldownTicks;  // 购买后冷却时间
    
    public ShopItem(Identifier id, Component displayName, int price, 
                   ItemStack icon, int maxPurchases, long cooldownTicks) {
        this.id = id;
        this.displayName = displayName;
        this.price = price;
        this.icon = icon;
        this.maxPurchases = maxPurchases;
        this.cooldownTicks = cooldownTicks;
    }
    
    public Identifier getId() { return id; }
    public Component getDisplayName() { return displayName; }
    public int getPrice() { return price; }
    public ItemStack getIcon() { return icon; }
    public int getMaxPurchases() { return maxPurchases; }
    public long getCooldownTicks() { return cooldownTicks; }
}

// 商店注册表（src/main/java/.../shop/ShopRegistry.java）
public final class ShopRegistry {
    private static final Map<Identifier, List<ShopItem>> SHOPS = new HashMap<>();
    private static final Map<UUID, ShopPlayerState> PLAYER_STATES = new HashMap<>();
    
    public static void registerShop(Identifier shopId, List<ShopItem> items) {
        SHOPS.put(shopId, items);
    }
    
    public static List<ShopItem> getShopItems(Identifier shopId) {
        return SHOPS.getOrDefault(shopId, Collections.emptyList());
    }
    
    public static ShopPlayerState getOrCreatePlayerState(UUID playerId) {
        return PLAYER_STATES.computeIfAbsent(playerId, uid -> new ShopPlayerState());
    }
    
    // 清理离线玩家数据（定期调用）
    public static void cleanupOfflinePlayers(Set<UUID> onlinePlayerIds) {
        PLAYER_STATES.keySet().retainAll(onlinePlayerIds);
    }
}

// 玩家购买状态（src/main/java/.../shop/ShopPlayerState.java）
public class ShopPlayerState {
    private final Map<Identifier, Integer> purchaseCount = new HashMap<>();  // 商品ID -> 已购买次数
    private final Map<Identifier, Long> cooldowns = new HashMap<>();  // 商品ID -> 下次可购买时间
    private int currency = 0;  // 玩家货币/积分
    
    public boolean canPurchase(ShopItem item, long currentTime) {
        // 检查次数限制
        if (item.getMaxPurchases() > 0) {
            int count = purchaseCount.getOrDefault(item.getId(), 0);
            if (count >= item.getMaxPurchases()) return false;
        }
        // 检查冷却
        long cooldownUntil = cooldowns.getOrDefault(item.getId(), 0L);
        return currentTime >= cooldownUntil;
    }
    
    public void recordPurchase(ShopItem item, long currentTime) {
        purchaseCount.merge(item.getId(), 1, Integer::sum);
        if (item.getCooldownTicks() > 0) {
            cooldowns.put(item.getId(), currentTime + item.getCooldownTicks());
        }
    }
    
    public void setCurrency(int amount) { this.currency = amount; }
    public int getCurrency() { return currency; }
    public int getPurchaseCount(Identifier itemId) { 
        return purchaseCount.getOrDefault(itemId, 0); 
    }
}
```

### 购买命令与网络同步

```java
// 购买请求包（C2S）
public class PurchaseItemC2SPacket implements CustomPayload {
    public static final PacketType<PurchaseItemC2SPacket> ID =
        new PacketType<>(new Identifier(NoellesRoles.MODID, "purchase_item"));
    
    private final Identifier shopId;
    private final Identifier itemId;
    
    public PurchaseItemC2SPacket(Identifier shopId, Identifier itemId) {
        this.shopId = shopId;
        this.itemId = itemId;
    }
    
    @Override
    public void write(RegistryByteBuf buf) {
        buf.writeIdentifier(shopId);
        buf.writeIdentifier(itemId);
    }
    
    public static PurchaseItemC2SPacket read(RegistryByteBuf buf) {
        return new PurchaseItemC2SPacket(buf.readIdentifier(), buf.readIdentifier());
    }
    
    @Override
    public PacketType<?> getType() { return ID; }
}

// 服务端处理（src/main/java/.../shop/ShopPacketHandler.java）
public class ShopPacketHandler {
    public static void registerHandlers() {
        ServerPlayNetworking.registerGlobalReceiver(
            PurchaseItemC2SPacket.ID,
            (payload, context) -> {
                ServerPlayer player = context.player();
                ShopPlayerState state = ShopRegistry.getOrCreatePlayerState(player.getUUID());
                List<ShopItem> items = ShopRegistry.getShopItems(payload.shopId);
                
                ShopItem item = items.stream()
                    .filter(i -> i.getId().equals(payload.itemId))
                    .findFirst()
                    .orElse(null);
                
                if (item == null) {
                    player.sendSystemMessage(Component.literal("商品不存在"));
                    return;
                }
                
                long currentTime = player.level().getGameTime();
                
                // 检查条件
                if (!state.canPurchase(item, currentTime)) {
                    player.sendSystemMessage(Component.literal("无法购买：次数限制或冷却中"));
                    return;
                }
                
                if (state.getCurrency() < item.getPrice()) {
                    player.sendSystemMessage(Component.literal("货币不足"));
                    return;
                }
                
                // 执行购买
                state.setCurrency(state.getCurrency() - item.getPrice());
                state.recordPurchase(item, currentTime);
                player.sendSystemMessage(
                    Component.literal("购买成功：" + item.getDisplayName().getString())
                );
                
                // 应用效果（如给予物品、应用BUFF等）
                applyPurchaseEffect(player, item);
            }
        );
    }
    
    private static void applyPurchaseEffect(ServerPlayer player, ShopItem item) {
        // 根据商品 ID 应用不同效果
        if (item.getId().getPath().startsWith("buff_")) {
            // 应用增益效果
            player.addEffect(new MobEffectInstance(MobEffects.REGENERATION, 600, 1));
        } else if (item.getId().getPath().startsWith("item_")) {
            // 给予物品
            player.addItem(item.getIcon().copy());
        }
    }
}
```

```java
public class ShopScreen extends Screen {
    private static final int ITEM_SIZE = 18;
    private static final int ITEMS_PER_ROW = 9;
    
    private final Identifier shopId;
    private final List<ShopItem> items;
    private ScrollingList itemList;
    
    public ShopScreen(Identifier shopId, List<ShopItem> items) {
        super(Component.literal("商店"));
        this.shopId = shopId;
        this.items = items;
    }
    
    @Override
    protected void init() {
        super.init();
        
        // 构建滚动列表
        this.itemList = new ScrollingList(
            this.width / 2 - 88,
            this.height / 2 - 96,
            176,
            166,
            ITEM_SIZE + 2,
            items.size()
        );
        
        this.addRenderableWidget(this.itemList);
        
        // 添加关闭按钮
        this.addRenderableWidget(
            Button.builder(Component.literal("关闭"), btn -> this.onClose())
            .pos(this.width / 2 - 30, this.height - 26)
            .size(60, 20)
            .build()
        );
    }
    
    @Override
    public void render(GuiGraphics guiGraphics, int mouseX, int mouseY, float partialTick) {
        this.renderBg(guiGraphics);
        super.render(guiGraphics, mouseX, mouseY, partialTick);
        
        // 绘制商品列表
        int startX = this.width / 2 - 88;
        int startY = this.height / 2 - 96;
        
        for (int i = 0; i < items.size(); i++) {
            ShopItem item = items.get(i);
            int x = startX + (i % ITEMS_PER_ROW) * (ITEM_SIZE + 1);
            int y = startY + (i / ITEMS_PER_ROW) * (ITEM_SIZE + 1);
            
            // 绘制商品图标
            guiGraphics.renderItem(item.getIcon(), x, y);
            
            // 绘制价格标签
            guiGraphics.drawString(
                this.minecraft.font,
                String.valueOf(item.getPrice()),
                x, y + ITEM_SIZE,
                0xFFFF00
            );
        }
    }
    
    @Override
    public boolean mouseScrolled(double mouseX, double mouseY, double scrollX, double scrollY) {
        return this.itemList.mouseScrolled(mouseX, mouseY, scrollX, scrollY);
    }
    
    @Override
    public boolean mouseClicked(double mouseX, double mouseY, int button) {
        // 检测点击商品
        int startX = this.width / 2 - 88;
        int startY = this.height / 2 - 96;
        
        for (int i = 0; i < items.size(); i++) {
            int x = startX + (i % ITEMS_PER_ROW) * (ITEM_SIZE + 1);
            int y = startY + (i / ITEMS_PER_ROW) * (ITEM_SIZE + 1);
            
            if (mouseX >= x && mouseX < x + ITEM_SIZE && 
                mouseY >= y && mouseY < y + ITEM_SIZE && button == 0) {
                // 发送购买请求
                ClientPlayNetworking.send(
                    new PurchaseItemC2SPacket(shopId, items.get(i).getId())
                );
                return true;
            }
        }
        
        return super.mouseClicked(mouseX, mouseY, button);
    }
    
    private void renderBg(GuiGraphics guiGraphics) {
        guiGraphics.fillGradient(
            0, 0, this.width, this.height,
            0xFF8B8B8B, 0xFF000000
        );
    }
}
```

## 开发流程建议

1. 创建或扩展角色：在角色表（代码/数据）定义 `roleId` 与能力集合。
2. 扩展组件：为新能力添加条件、冷却、效果实现，确保服务端判定与客户端显示分离。
3. 注册钩子：在入口类中注册新事件或能力回调，必要时添加 Mixins 注入点。
4. 测试与调试：使用 `runClient`、`runServer`，观察日志与崩溃报告，完善边界条件。
5. 客户端屏幕：创建自定义 `Screen` 类，注册渲染与交互回调，通过 C2S 包与服务端通信。
6. 商店扩展：定义 `ShopItem`，注册到 `ShopRegistry`，在客户端屏幕中展示并处理购买。

## 常见问题

- 组件未同步：确认实现了 `AutoSyncedComponent`，并在服务端状态变更后触发同步。
- 客户端逻辑越权：判定必须在服务端进行，客户端仅做 UI 与提示。
- Mixins 冲突：缩小注入范围，避免覆盖其他 Mod 的核心逻辑，必要时提供兼容层。
